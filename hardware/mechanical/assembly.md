# Assembly

ลำดับการประกอบ และค่าที่ **ต้องวัดระหว่างประกอบ** เพราะวัดทีหลังไม่ได้

---

## ลำดับ

```text
1. แผ่นแชสซี + ขายึดมอเตอร์
2. มอเตอร์ 4 ตัว + ล้อ
3. ตู้/ถาดอิเล็กทรอนิกส์ (วางให้ต่ำที่สุด)
4. H-bridge driver + ตัวเก็บประจุ
5. E-stop + สวิตช์หลัก + ฟิวส์
6. ESP32 + buck logic
7. Raspberry Pi + buck Pi
8. เสากล้อง + กล้อง 2 ตัว
9. แบตเตอรี่ (ต่ำสุดเท่าที่ทำได้)
10. เดินสาย + drag chain ไปเสากล้อง
11. **ทดสอบล้อลอยบนโต๊ะให้ผ่านครบ** ◄── ข้ามไม่ได้
12. วัดค่า + calibrate กล้องล่าง
13. วางลงแปลง
```

**ขั้นที่ 11 ข้ามไม่ได้** — ต่างจาก gantry ที่เคลื่อนที่เองไม่ได้ rover ที่วางลงพื้น
ก่อนทดสอบ safety คือ rover ที่อาจวิ่งหนีตอนที่การทดสอบล้มเหลว
ดู [../../docs/hardware.md](../../docs/hardware.md#hardware-in-the-loop--ต้องล้อลอย)

แบตเตอรี่และมอเตอร์ต้องอยู่ **ต่ำสุด** เพราะเสากล้อง 220 mm บนรถกว้างรวมล้อ 146 mm
ทำให้จุดศูนย์ถ่วงสูงอยู่แล้ว

## ค่าที่ต้องวัดระหว่างประกอบ

| ค่า | วัดตอนไหน | บันทึกที่ |
|---|---|---|
| `wheel_diameter_mm` จริง (รวมยาง) | หลังใส่ล้อ | `config/rover.yaml` |
| `track_width_mm` จริง | หลังใส่ล้อ | `config/rover.yaml` |
| `body_width_mm` จริง (**จุดกว้างสุด**) | หลังใส่ล้อ | `config/rover.yaml` |
| `chassis_clearance_mm` จริง | หลังใส่ล้อ พร้อมน้ำหนักครบ | `config/rover.yaml` |
| **`wheel_v_min_mm_s`** (deadband) | ขั้นที่ 11 ล้อลอย | `config/rover.yaml` |
| `camera_down` homography | หลังติดกล้อง | `config/camera.yaml` |
| `soil_variation_mm` | หลังปรับหน้าดิน | `config/rover.yaml` |
| `runaway_budget_mm` ที่วัดได้จริง | หลังวางลงแปลง | `config/safety.yaml` |

`chassis_clearance` ต้องวัด **พร้อมน้ำหนักครบ** — ยางกดตัวลงหลายมิลลิเมตร
ค่าที่วัดตอนยกรถลอยจะสูงกว่าจริง แล้วท้องรถจะครูดยอดดินที่ invariant บอกว่าผ่าน

### `body_width_mm` — วัดที่จุดกว้างสุด ไม่ใช่แชสซี

```text
       ◄── 146 ──►
    ┌──┬────────┬──┐
    │██│แชสซี 140│██│    ██ = ล้อ ยื่นออกข้างละ 3 mm
    └──┴────────┴──┘
```

ใช้เวอร์เนียร์วัดจากขอบยางซ้ายถึงขอบยางขวา **ไม่ใช่จากขอบแผ่นแชสซี**

ถ้าบันทึกความกว้างแชสซี (140) ลง config แทนความกว้างรวม (146)
invariant ข้อ 5 จะผ่านโดยที่ล้อยังเบียดใบพืช — ระบบจะ "ดูเหมือนปลอดภัย"

### `wheel_v_min_mm_s` — ต้องวัด ไม่มีทางคำนวณ

ค่า 51 ใน config เป็นการเดาจาก 15% duty **ยังไม่ได้วัด**

```text
[ ] ยกล้อลอย จ่ายไฟมอเตอร์
[ ] สั่ง duty เริ่มจาก 0 เพิ่มขึ้นทีละ 1%
[ ] บันทึก duty ต่ำสุดที่ล้อเริ่มหมุนต่อเนื่อง (ไม่ใช่กระตุกครั้งเดียว)
[ ] ทำซ้ำทั้ง 4 ล้อ — ใช้ค่าที่แย่ที่สุด
[ ] wheel_v_min_mm_s = duty_min × wheel_v_max_mm_s
[ ] วางรถลงพื้นแล้ววัดซ้ำ — แรงเสียดทานพื้นทำให้ค่าสูงขึ้น ใช้ค่านี้
```

ถ้าค่าที่วัดได้ **เกิน 58 mm/s** → ต้องลด `omega_max_deg_s` (เพดานคือ 46)
**ห้ามลด `wheel_v_min` เพื่อให้ invariant ผ่าน** — ค่านั้นเป็นคุณสมบัติของมอเตอร์
ไม่ใช่ค่าที่เราเลือก

### `soil_variation_mm`

หลังปรับหน้าดินเรียบที่สุดเท่าที่ทำได้ ให้วัดจริง:

```text
[ ] ขึงเชือกตึงตามแนวร่อง ให้เป็นระนาบอ้างอิง
[ ] วัดระยะจากเชือกลงถึงผิวดินทุก 100 mm ตลอด 2000 mm (20 จุด)
[ ] ทำ 2 ร่อง
[ ] soil_variation_mm = (สูงสุด − ต่ำสุด) / 2
```

ไม่ใช้ tool วัดเหมือน design gantry เพราะ MVP ไม่มี tool

ถ้าค่าที่วัดได้ **เกิน 16 mm** → invariant `wheel_diameter >= 4 × soil_variation`
ไม่ผ่าน (margin เหลือแค่ 5 mm) ต้องเลือก: ปรับหน้าดินใหม่ หรือเปลี่ยนล้อใหญ่ขึ้น
**ไม่ใช่แก้ config ให้ผ่าน**

### `runaway_budget_mm` — วัดหลังวางลงแปลง

```text
[ ] วาง rover ในร่อง ให้กันชนหน้าอยู่ตำแหน่งเริ่มต้นปกติ
[ ] วัดระยะจากกันชนหน้าถึงขอบแปลงปลายร่อง
[ ] วัดระยะจากด้านข้างล้อถึงใบพืชที่ยื่นเข้าร่องมากที่สุด
[ ] runaway_budget_mm ต้องเล็กกว่าทั้งสองค่า
```

ค่า 60 ใน config เป็นค่าตั้งต้น ถ้าวัดจริงแล้วน้อยกว่า ต้องลด `runaway_budget`
แล้ว **re-validate invariant safety ทั้งสองข้อ** ซึ่งอาจต้องลด `v_max`
หรือ `command_timeout_ms` ตามไปด้วย

## Tolerance ที่สำคัญ

| จุด | Tolerance | ทำไม |
|---|---|---|
| เพลาล้อทั้ง 4 ขนานกัน | ±0.5° | ไม่งั้น rover ไถลเฉียงตลอดเวลา row follower จะต้านมันทุกเฟรม |
| ล้อซ้าย/ขวาเส้นผ่านศูนย์กลางเท่ากัน | ±0.5 mm | ต่างกันทำให้วิ่งตรงแล้วเบี่ยง — อาการเหมือน gain ผิด แต่แก้ที่ gain ไม่ได้ |
| กล้องล่างขนานกับ soil plane | ±1° | มุมก้มทำให้ error จากดินไม่เรียบใหญ่ขึ้น |
| **กล้องหน้า มุมก้ม** | **±2°** | **กำหนด lookahead → กำหนด gain** เปลี่ยนแล้วต้อง tune ใหม่ |
| เสากล้องไม่โยก | — | ภาพสั่นทำให้ valley histogram แกว่ง → omega กระตุก |

### ล้อคนละขนาดคือกับดักที่หายากที่สุด

ล้อขวาใหญ่กว่าซ้าย 1 mm (1.5%) ทำให้ rover เบี่ยงซ้ายอย่างต่อเนื่องแม้สั่ง
`omega = 0` row follower จะชดเชยได้ (มันปิดลูปด้วยภาพ) แต่มันจะกิน
พิสัย `omega` ไปส่วนหนึ่งตลอดเวลา ทำให้ความสามารถในการแก้ error จริงลดลง

อาการจะดูเหมือน "gain ไม่พอ" ทั้งที่ปัญหาเป็น mechanical — **วัดล้อก่อน tune gain**

### เพลาไม่ขนานแก้ด้วย software ไม่ได้

skid-steer พึ่ง slip อยู่แล้ว ถ้าเพลาเฉียงด้วย ทิศทางการ slip จะไม่สมมาตร
ทำให้ `omega` ที่ได้ต่างกันระหว่างเลี้ยวซ้ายและเลี้ยวขวา — gain ตัวเดียว
ชดเชยไม่ได้ทั้งสองทาง

## Pre-power Checklist

ก่อนจ่ายไฟครั้งแรก:

```text
[ ] หมุนล้อทั้ง 4 ด้วยมือได้อิสระ ไม่ติดขัด ไม่ฝืด
[ ] ล้อทั้ง 4 แตะพื้นพร้อมกันบนพื้นเรียบ (ไม่มีล้อลอย)
[ ] วัดล้อทั้ง 4 — เส้นผ่านศูนย์กลางต่างกันไม่เกิน 0.5 mm
[ ] วัด body_width ที่จุดกว้างสุด (ขอบยางถึงขอบยาง) แล้วบันทึกลง config
[ ] สายไม่พันกับล้อตลอดการหมุน
[ ] E-stop ตัดไฟมอเตอร์ได้จริง (วัดด้วยมิเตอร์ ไม่ใช่เชื่อวงจร)
[ ] E-stop **ไม่** ตัดไฟ Pi และ ESP32 (วัดด้วยมิเตอร์)
[ ] ขั้วไฟไม่กลับ วัดแรงดันก่อนเสียบ Pi และ ESP32
[ ] ตัวเก็บประจุ 1000 µF ขั้วถูกต้อง
[ ] GND ของ Pi, ESP32, driver ต่อร่วมกันที่จุดเดียว
```

การทดสอบ E-stop ด้วยมิเตอร์ก่อนจ่ายไฟจริงเป็นขั้นที่ข้ามไม่ได้ —
E-stop ที่ต่อผิดจะดูเหมือนทำงานจนถึงวันที่ต้องใช้จริง

**และต้องทดสอบทั้งสองทิศทาง**: ตัดมอเตอร์ได้ **และ** ไม่ตัด logic
ถ้าตัด logic ด้วย จะได้ rover ที่หยุดจริงแต่เงียบ — controller จะเห็นเป็น
`communication_lost` แทน `emergency_stop`

## Bench Test Checklist — ล้อลอย (ขั้นที่ 11)

ยกล้อลอยบนโต๊ะ ให้ผ่านครบก่อนวางลงพื้น

```text
Firmware / safety
[ ] ถอดสาย serial ระหว่างวิ่ง → มอเตอร์ดับภายใน 300 ms (วัดด้วย scope / log)
[ ] กด E-stop ขณะ Pi ยังส่ง drive → ล้อหยุด
[ ] ปล่อย E-stop แล้วสั่ง reset ขณะยังกดอยู่ → ถูกปฏิเสธ
[ ] ยัด drive 50 ตัวเข้า buffer → ใช้ตัว seq สูงสุดตัวเดียว
[ ] ส่ง seq ย้อนหลัง → ถูกทิ้ง
[ ] ปิด-เปิด ESP32 → uptime_ms ลดลง controller ตรวจจับได้

Motion
[ ] ตรวจทิศทาง: drive(+100, 0) → ล้อทั้ง 4 หมุนไปข้างหน้า
[ ] ตรวจทิศทาง: drive(0 < v, omega > 0) → ล้อขวาเร็วกว่าซ้าย (เลี้ยวซ้าย)
[ ] วัด wheel_v_min ทั้ง 4 ล้อ → ใช้ค่าแย่สุด
[ ] re-validate invariant drive ตัวล่างด้วยค่าที่วัดได้

Power
[ ] สั่งออกตัวเต็มกำลัง → แรงดันที่ Pi ไม่ตกต่ำกว่า 4.8 V
[ ] Pi ไม่รีบูตตลอดการทดสอบ
```

### ทิศทางที่กลับด้านคือกับดักที่แพงที่สุด

ถ้า `omega > 0` ทำให้เลี้ยว **ขวา** แทนซ้าย row follower จะกลายเป็น
positive feedback — rover จะออกนอกร่องเร็วขึ้นแทนที่จะกลับเข้าร่อง

แก้ได้ทั้งใน firmware หรือสลับสายมอเตอร์ — **เลือกแก้ใน firmware แล้วบันทึกไว้**
จะได้ไม่สับสนตอนเปลี่ยนมอเตอร์

ดู [coordinate-frames.md](coordinate-frames.md#rover--frame-หลักของ-mvp) สำหรับ sign convention
